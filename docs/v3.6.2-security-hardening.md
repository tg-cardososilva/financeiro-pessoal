# v3.6.2 - Hardening de Seguranca e Banco

Baseline: v3.6.1.

Esta versao nao adiciona funcionalidades de produto, nao altera UX e nao muda o cache-bust do frontend. O objetivo e reduzir divida de seguranca e performance de baixo risco antes de novos modulos.

## Auditoria inicial

### Supabase Auth

O Security Advisor reportava `Leaked Password Protection Disabled`.

O projeto esta no plano Supabase Free. A protecao de senha vazada via HaveIBeenPwned e recurso do plano Pro ou superior, portanto o alerta permanece por limitacao do plano. Nenhuma politica de autenticacao, login, cadastro, recuperacao ou sessao foi alterada nesta versao.

### Tabelas backend-only

`public.jarvis_connection_secrets` e `public.jarvis_oauth_states`:

- RLS habilitado;
- zero policies, intencionalmente;
- zero grants para `anon`;
- zero grants para `authenticated`;
- acesso de tabela mantido somente para `service_role`;
- usadas por Edge Functions/backend privilegiado.

O advisor `RLS Enabled No Policy` nessas duas tabelas e um falso positivo operacional para o modelo escolhido: sem grant e sem policy, o cliente publico nao tem caminho de acesso. Nao foram criadas policies artificiais apenas para silenciar o advisor.

### Data API e RLS

Todas as tabelas publicas auditadas que possuem grants de cliente estao com RLS habilitado. Nao foram encontradas policies com `USING (true)`, `auth.role()` ou autorizacao por `user_metadata`.

Policies modernas de Tarefas, Notas, Projetos, Arquivos, Documentos Inteligentes e conexoes Jarvis ja utilizavam `(select auth.uid())`.

### Policies legadas

O Performance Advisor reportava 20 ocorrencias de `auth_rls_initplan`, todas em policies legadas de owner que chamavam `auth.uid()` por linha e estavam declaradas para `PUBLIC`.

A v3.6.2 altera somente essas 20 policies para:

- `TO authenticated`;
- mesmo predicado de ownership anterior;
- `(select auth.uid())` em `USING` e `WITH CHECK`.

Nao existe ampliacao de acesso. Para usuarios autenticados, a semantica de ownership permanece a mesma; para roles anonimas, a policy fica explicitamente indisponivel.

### FKs sem indice

O advisor reportava 31 foreign keys sem indice de cobertura. A maior tabela envolvida no momento da auditoria era `transactions`, com 176 registros; varias tabelas estavam vazias.

Nenhum indice foi criado somente para eliminar warnings. Esses achados permanecem como itens de observacao e devem ser revisitados quando volume e planos de consulta justificarem custo de escrita/armazenamento adicional.

### Indices `unused`

O advisor reportava 13 indices ainda nao utilizados. Nenhum foi removido. O banco e recente e varias tabelas possuem uso baixo ou nulo; ausencia de scans acumulados nao demonstra que um indice seja desnecessario.

### Edge Functions sem verify_jwt

Somente tres funcoes continuam com `verify_jwt = false`:

1. `jarvis-google-oauth`: necessario para callback OAuth GET. Inicio POST valida manualmente Bearer JWT; callback valida state aleatorio, expiracao e uso unico.
2. `jarvis-google-drive-oauth`: necessario para handoff OAuth GET. Inicio POST valida manualmente Bearer JWT; GET valida state temporario e valido.
3. `jarvis-whatsapp-webhook`: endpoint publico da Meta. O GET valida verify token. O POST atual permanece no estado diagnostico existente e nao foi alterado nesta versao por decisao explicita de escopo.

O webhook do WhatsApp permanece como divida conhecida: validacao criptografica do POST e reducao de logging devem ser tratados em uma versao dedicada, sem misturar com este hardening.

### Secrets

O frontend usa somente a chave Supabase publishable. Nenhuma service key/service_role, Google client secret, OpenAI API key, HMAC secret ou credencial de service account foi movida para o navegador. Segredos continuam em Edge Function Secrets/backend.

## Alertas apos a correcao

Esperado:

- `auth_rls_initplan`: 0;
- `rls_enabled_no_policy`: 2, intencionais (`jarvis_connection_secrets`, `jarvis_oauth_states`);
- `auth_leaked_password_protection`: 1, bloqueado pelo plano Free;
- `unindexed_foreign_keys`: 31, sem justificativa de volume para alteracao nesta versao;
- `unused_index`: 13, mantidos por ausencia de evidencia para remocao.

## Guardrails

- nenhuma exclusao ou alteracao de registros reais;
- nenhuma migration de dados;
- nenhuma policy mais permissiva;
- nenhuma mudanca de OAuth scopes;
- nenhuma mudanca de Edge Functions;
- nenhuma mudanca de frontend ou cache-bust;
- nenhuma escrita automatica adicionada no carregamento das telas;
- Calendar, Drive/JARVIS, Documentos Inteligentes, Tarefas, Notas, Projetos, Financas e WhatsApp preservados funcionalmente.
